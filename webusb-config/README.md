# ESP32 BLE Remote Bridge · WebUSB 配置站点

这是一个纯静态网页，通过浏览器 **WebUSB API** 直接与 ESP32 BLE Remote Bridge 固件通信，
替代了原 RemoteMapper-ESP32 的 Wi-Fi 热点 + HTTP 网页配置方案。

## 功能

* 设备状态：固件版本、运行时间、BLE 状态、当前配置、音频帧数、内存占用
* 按键配置：5 个配置方案可视化编辑（单击 / 长按 / 双击 / 连发），支持键盘、多媒体、鼠标按键与鼠标移动/滚轮，并支持继承穿透；可视化键盘外提供「扩展按键」下拉框（F13-F24、撤销/剪切/复制/粘贴等常用键）；语音动作提供常用「语音快捷键」选择，鼠标滚轮以「方向 + 格数」配置；「语音设置…」可选语音键触发方式（按一下开关 / 按住说话）、快捷键发送方式（全程按住 / 开始结束各按一下 / 仅开始按一下）与单次最长时长
* 按键学习：实时显示「刚按下的是第几个物理槽位」，可给槽位起自己的名字（存在设备 NVS 里），
  并一键跳到该槽位的按键映射。见下文[按键学习](#按键学习)
* 配置切换：通过「按键配置」页的「配置切换模式…」按钮弹窗编辑全局切换映射（确定键锁定为默认配置，仅可修改四个方向键对应的配置）；固件默认长按电视键进入切换模式，也可在按键配置中把任意动作设为「进入配置切换模式」
* 蓝牙配对：扫描、连接、重新连接、解除绑定
* 实时同步：状态每秒刷新，设备侧配置变更（`config_rev`）自动重新读取，标签页切回 / 窗口聚焦时立即刷新
* 运行日志：查看 / 清空设备日志
* 系统设置：重启、恢复出厂、原始 JSON 导入导出

## 按键学习

Google TV Remote 上报的是**按 HID 报告分开的 1 字节按钮索引**，它本身不含任何语义，也**不是**
槽位号（这台遥控器有主 `0x0021`、副 `0x001D` 两条报告，各自从 1 开始编号，所以「索引 1」有两个
不同的按键）。固件按 `(报告, 索引)` 查规范化键码表，映射到共享键码，再落到固定的物理槽位；
因此**槽位（以及它对应的规范键码）才是按键唯一且稳定的身份**：

* **显示名称** —— 在「按键学习」里改，存在设备 NVS 中，用来让你看懂哪个槽位是遥控器上的哪个键；
* **实际动作** —— 在「按键配置」里改，决定这个槽位往主机发什么。

两者互不影响。同一个槽位可以叫「返回」却映射成 `Alt+←`。

用法：

1. 按一下遥控器上的按键 —— 页面顶部的读数会显示它是第几个槽位（原始索引不会显示在这里：
   它在两条报告里会重号，需要看时请到「运行日志」页打开 `raw report`，对照固件日志
   `HOGP: button chr#N idx=M -> key 0xXX (name) DOWN`，`chr#N` 是报告，`idx=M` 是它在该报告里的索引）；
2. 想确认某一行的确对应这个键：点该行的「检测」，再按下那个键，该行会闪烁；
3. 改名字（留空 = 恢复默认），点「保存名称」；
4. 点「去映射」直接跳到「按键配置」修改这个槽位的动作。

要点：

* 名称按 **UTF-8 字节**计算，上限 **31 字节**（约 10 个汉字）。输入框旁会实时显示用量，
  超出部分保存时按**字符边界**截断，不会出现半个汉字。
* 名称是**按设备保存**的，换一台遥控器 / 清空 NVS 后回到出厂名称。
* 「最近按下」是按**按下瞬间**记录的，短于约 150 毫秒的极轻触可能被轮询漏掉 —— 按实一点。
* 老固件（没有 `KEY_NAMES_GET` / `KEY_NAMES_SET`）下页面会提示并停用改名，
  但「实时检测」「检测」「去映射」照常可用。

> 出厂名称是**按标准 Google TV 遥控器的顺序猜的**（当时假设 `索引 N = 槽位 N-1` 的单报告恒等映射，
> 对 RC003 成立，对 ZTKA-IR57 这种双报告遥控器不成立）。不同型号的按键与索引对应关系不一样时，
> 默认名字会和实物对不上 —— 以实测为准：**按下哪个键，亮起来的就是它**，然后改名即可。
> 权威对照表见 [`docs/GOOGLE-TV-REMOTE-ZTKA-IR57.md`](../docs/GOOGLE-TV-REMOTE-ZTKA-IR57.md) 第 1 节。

## 本地运行

WebUSB 要求页面处于安全上下文，`http://localhost` 属于安全来源：

```bash
cd webusb-config
python -m http.server 8000
```

然后打开 <http://localhost:8000/>，点击「连接设备」，选择固件的 USB 产品名 `MI-RC003 Remote Bridge`。

## 部署

将本目录上传到任意 **HTTPS** 静态托管（GitHub Pages / Cloudflare Pages / 自有服务器）即可。
若部署地址不是 `localhost:8000`，请同步修改固件 `main/version.h` 中的：

```c
#define WEBUSB_LANDING_URL     "your.site/path/"
#define WEBUSB_LANDING_SCHEME  1   // 0 = http, 1 = https
```

## 在线烧录页面

`flash/` 子目录是基于 [ESP Web Tools](https://esphome.github.io/esp-web-tools/) 的**浏览器固件烧录页**，
部署后访问 `https://<站点>/flash/`，用桌面版 Chrome / Edge 即可直接烧录固件（Web Serial）。

页面文件：`flash/index.html`、`flash/boards.json`、`flash/manifest-<板型>.json`、
`flash/firmware/merged-flash-<板型>.bin`。页面通过 `boards.json` 列出可用板型（N16R8 / N8R2 /
N4R2），用户选择后加载对应的 `manifest-<板型>.json` 再烧录。
其中 manifest、板型清单与固件均由根目录 `build-firmware.bat` 自动生成，请勿手工编辑。

## 通信协议

请求与响应均使用如下帧格式（详见仓库根目录 README）：

```text
'M' 'R'  cmd  status  len_lo  len_hi  payload...
```

`assets/mi-rc003.js` 封装了组帧、发送与响应解析（`dev.send(cmd, payload)`），
`assets/app.js` 只是基于该库的默认界面。第三方可只引入 `mi-rc003.js` 自行构建 UI。

## 兼容性

* 桌面版 Chrome / Edge（Windows / macOS / Linux）
* Windows 10/11 自动绑定 WinUSB，无需 Zadig
* Linux 需配置 udev 规则
* 移动端浏览器不支持 WebUSB
